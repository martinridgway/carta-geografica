**Real bug caught and fixed during in-browser verification**: the first version of `exportMapImage` waited on OL's `rendercomplete` event before compositing, following the pattern from OL's own "Export Map to PNG" example — but that event only fires for a render OL considers new/dirty, and by the time a user clicks an export button the map is always already idle, so the promise hung forever (confirmed directly: registered a one-off `rendercomplete` listener, called `renderSync()`, event never fired after a 500ms wait). Fixed by reading the already-rendered canvases synchronously instead of waiting on any event. Verified after the fix: clicking "Send to Shield" reached the fetch call immediately (confirmed via network tab) and failed gracefully with "Failed to fetch" while the companion server wasn't running, exactly as expected.

**Paused deliberately, not blocked**: Martin wants map-side features and display quality settled first, before spending more time on Shield delivery. `VITE_ENABLE_SHIELD_CAST` is set to `false` in `.env.local` (button hidden), `HA_TOKEN` is left blank (so `npm run server` refuses to start even if run by accident). To resume: get a Home Assistant long-lived access token (profile → Security tab → Create Token), fill in `HA_TOKEN`, set `VITE_ENABLE_SHIELD_CAST=true`, `npm run server`, click "Send to Shield," and confirm on the physical TV.

## Initial survey (2026-07-29)

Repo cloned from `github.com/martinridgway/carta-geografica` (public, AGPL-3.0) into this local project folder — first time Martin has touched it in years. Nothing built or run yet this session; this entry is a survey of what exists, not a changelog of work done.

**What it is**: a small React app (CRA/`react-scripts` 2.1.8, ~2019) that draws one OpenLayers map, centered on a hardcoded Boston coordinate (`src/App.js`), styled with the Stamen "watercolor" tile layer, with a title panel overlay showing city/state (via Nominatim reverse geocoding) and lat/lon in DMS. The pitch (README) is a wall-mounted art-map display — pick a location, get a beautiful map "poster."

**Two known-dead dependencies, confirmed by hitting them directly:**
- Stamen's free tile endpoint (`stamen-tiles.a.ssl.fastly.net`) returns `503`. Stamen's watercolor/terrain tiles moved under Stadia Maps in 2023 and now require a Stadia API key for meaningful use — `ol/source/Stamen` in OpenLayers 5 talks to the old dead endpoint, so **the map currently cannot render at all**, key or no key, without code changes (either swap the tile source or move to OL's newer Stadia-aware source, depending on what OL 5 supports vs. upgrading OL).
- `react-scripts@2.1.8` is CRA-era tooling from 2019, built for Node ~8-11 (README pins Node v11.11). Local Node is v26.4.0 — a 2019 CRA toolchain will very likely fail outright on a Node this new (webpack/babel version mismatches, `fs`/OpenSSL breaking changes). Not yet tested; expect `npm start`/`npm install` to need real intervention (upgrade CRA, migrate to Vite, or pin Node via nvm) before anything runs.

**Branches on `origin` worth knowing about:**
- `master` (default, checked out) — the state described above.
- `geocoding` — one commit ahead of an earlier point on `master` (`f6b375b`), adds forward geocoding (`src/location.js` hardcodes `"Boston, MA"`, `App.js` calls Nominatim `/search` instead of `/reverse`, only renders `<Map>` once coordinates resolve). Diffed against current `master`: not yet merged, and conflicts a little with `master`'s later history (`master` moved on after the point `geocoding` branched from). Worth a look before deciding whether forward-geocoding-from-a-typed-address is a feature to bring forward.
- ~20 `dependabot/npm_and_yarn/*` branches — stale automated dependency-bump PRs, all pre-dating this session, none merged. Likely safe to close once the dependency tree is actually reworked (upgrading past `react-scripts` 2.1.8 will obsolete most of them anyway); not touched yet.

**Leftover pre-React files at repo root**: `index.bak.html` / `index.bak.js` are the original Parcel-bundler-era prototype (before the "Mostly converted to react app" commit) — same map logic, vanilla JS, imports a `styles.css` that no longer exists at root (`styles.css` now differs, `src/index.scss` is the one actually wired into the React app). Dead code kept around by history, not referenced by `package.json` or the build. Candidate for deletion once we're sure nothing needs porting from it.
